## 2. Before / after

| Topic | Before | After |
|---|---|---|
| Where data lives | Each visitor's browser (localStorage) | PostgreSQL. Admin edits appear on every device (tested with separate browser contexts) |
| Admin login | Checked in the browser; `admin/admin123` default; bypassable in DevTools | Server sessions, Argon2id, CSRF, lockout, rate limit, 7 roles / 16 permissions, department scope, audit log. No default account |
| Prices and totals | Calculated in the browser | Calculated and enforced on the server; client-sent prices rejected |
| Stock | One number per product; no locking | Per-size inventory, row locks, reservations with expiry, append-only movement history; no overselling in concurrency tests and in a 4,893-order load test |
| Payments | Labels only | PayHere sandbox with signature verification; COD and bank transfer with staff verification; refunds; chargeback review |
| Customer accounts | Profile made from the first order, per device | Real accounts (email + password, verification and reset tokens); guest checkout with private tracking token; no cross-customer access |
| Photos | Base64 in localStorage (about 5 MB limit) | Uploaded files (local disk or S3/R2), type checked by content |
| Backups | None | pgBackRest full/diff + WAL to encrypted S3; restore test, PITR and tamper detection proven in a drill |
| Design | — | Unchanged. API-mode screenshots match the baseline (`e2e/out/*.jpg`, generated by the e2e run) |

## 3. Tests actually run (this environment: Linux container, Node 22.23, PostgreSQL 16.15, pgBackRest 2.50, Chromium via Playwright 1.63)

| Suite | Command | Result |
|---|---|---|
| API unit/integration against real PostgreSQL (fresh DB per run) | `cd server && npm test` | **69 / 69 passed** (run repeatedly; files are order-independent) |
| Type check | `npm run typecheck` | **pass** |
| Browser end-to-end against the running API (2 devices, COD, PayHere redirect + signed notify, accounts, uploads, mobile) | `node e2e/api-e2e.mjs` | **27 / 27 passed** |
| Demo-mode regression (old offline site) | `e2e/demo-mode/*` | **all passed** (63 routes × 5 widths, admin × 3 widths, XSS, empty catalogue, blocked storage, form validation) |
| Backup / DR drill | `infra/backup/drill/run-local-drill.sh` | **all steps PASS**: full + diff backup, check, restore test, PITR after an accident (all counts identical), total server loss with 70 s of data lost (`archive_timeout=60`), tamper detection, encryption |
| Image backup | `images-sync.sh` with rclone (local remotes) | **pass**: deleted/overwritten images kept under `_deleted/<date>/` |
| Docker image | `docker build` + run against PostgreSQL | **pass**: non-root, migrations inside the image, docs off in production, graceful stop |
| Load test (2 pinned cores, not the real VPS) | `node e2e/load/load-test.mjs` | **0 % errors** in every scenario; checkout 244 orders/s, p95 ≈ 193 ms; no overselling (`docs/budget-and-capacity.md`) |
| CI workflow | `.github/workflows/ci.yml` | **written, not yet run on GitHub** (it runs on the next push to the branch) |

**Defects found by these tests and fixed:**
- Failed staff logins returned HTTP 500, so account lockout never applied (a parameter typing bug).
- Finance staff could not record refunds (the cancel route required the wrong permission).
- The catalogue snapshot only managed 115 requests/s; a cache took it to 1,652/s.
- `pgbackrest verify` exits 0 even when it finds damaged files, so the restore test now reads its report.
